# Quality

Where the quality of this repository is checked, and where to look to see its
current state. Everything here is generated by the gates and GitHub; this page
only says where it lives, so it never goes stale.

## The gates

`scripts/gates.sh` is the single definition of "the site is fine". A person,
the pre-push hook, CI, and the nightly run all call it.

| Gate | Fails when |
|---|---|
| `branch-name` | The branch name is outside the vocabulary in `scripts/check-branch-name` |
| `build` | `hugo --gc --minify` fails at the version pinned in `netlify.toml` |
| `feed` | `/index.xml` or `/blog/index.xml` does not parse, misses posts, carries only summaries, or has root-relative links |
| `no-theme-edit` | `themes/hugo-bearblog` has local changes or is not at the pinned commit |
| `docs-links` | A pointer file does not link to `AGENTS.md`, or a relative link in the Markdown docs does not resolve |

`tests/run` proves each gate catches its failure: it plants a break, expects
the gate to fail, restores, and expects it to pass. A new gate is not done
until it has such a suite.

## Dashboard

There is no separate dashboard service; these GitHub views are the dashboard.

| Question | Where to look |
|---|---|
| Is `main` green right now? | Actions, workflow `nightly` (runs daily, and on demand) |
| Did this PR pass? | The PR's checks: `branch-name`, `gates`, `Analyze (actions)` |
| Are there code-scanning alerts? | Security, Code scanning (CodeQL for `actions`) |
| Does the live site build? | Netlify deploys for the site, and each PR's deploy preview |
| How is the repository doing over time? | [docs/metrics.md](metrics.md) |

## Known gaps

Recorded on purpose, so they are not mistaken for oversights:

- No end-to-end or visual tests. Layout changes are checked by eye in the
  deploy preview.
- No coverage measurement; the shell and Python in `scripts/` are covered by
  the planted-failure suites in `tests/run` instead.
- The feed is checked for structure and full content, not against the W3C
  Feed Validator, which is a manual step on the deploy preview.
